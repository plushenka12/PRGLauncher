# PRGLauncher / PRGTracker

Персональний лаунчер і трекер ігор для Windows. PRGLauncher є основним
локальним застосунком, а PRGTracker — read-only веб-відображенням статистики.

## Філософія

Steam працює як бекенд, а не як головний інтерфейс. У щоденній роботі ти
користуєшся PRGLauncher: бібліотекою, таймерами, Backlog і статистикою. Steam
запускається у фоні лише тоді, коли це потрібно для запуску або встановлення
гри.

## Що вміє лаунчер

### Бібліотека

- Додавання і редагування ігор.
- Стани `Playing`, `Backlog`, `Completed`.
- Пошук назв і метаданих через RAWG.
- Обкладинки, жанри, теги, оцінка, платформа, нотатки та рік додавання.
- Фільтри за статусом, роком, рейтингом і платформою.
- Ручне редагування загального часу та окремих сесій.
- Синхронізація бібліотеки через Firestore.

### Backlog-режим

- Імпорт нових ігор із Steam-колекції `BACKLOG`.
- Перший запуск створює baseline: старі записи не імпортуються автоматично.
- Після baseline лаунчер повідомляє лише про нові додані App ID.
- Назви та обкладинки для імпорту отримуються зі Steam Store API.
- Для кожної нової гри можна одразу вибрати статус.
- Пріоритети `Later`, `Soon`, `Now`.

### Steam

- Виявлення Steam через реєстр Windows і стандартні каталоги.
- Перевірка встановлення гри через `appmanifest_*.acf`.
- Сторінка `Downloads` із реальним прогресом із локальних Steam-файлів.
- Якщо завантаження скасувати у Steam, лаунчер переходить у стан
  «Завантаження скасовано в Steam».
- Steam не ховається безперервно: ручне відкриття з трею залишається видимим.
- Після дії, ініційованої лаунчером, Steam автоматично ховається назад.

### GOG Galaxy (Beta)

- `Settings → Integrations → Імпорт встановлених GOG-ігор` читає локальні записи
  GOG Galaxy з Windows registry.
- Імпорт не відкриває web-login, не просить пароль і не зберігає cookies.
- Картка отримує `sources: [{ type: 'gog', id, platform: 'PC' }]`, локальний
  install path та executable.
- Запуск виконується напряму з executable, а якщо він недоступний — через
  `goggalaxy://openGameView/<id>`.
- Це local MVP: повна акаунтова бібліотека, cloud playtime та live download
  progress GOG поки не входять у підтримку.

### Автоматичний трекінг сесій

- Лаунчер стежить за `Running=1` у Steam-реєстрі Windows.
- Якщо прив’язана до App ID гра реально запустилася, таймер стартує автоматично.
- Після завершення гри таймер зупиняється, сесія записується, час додається до гри.
- Запуск через кнопку лаунчера не створює фальшивий таймер до фактичного старту.
- Ручні таймери для не-Steam ігор не перериваються Steam-монітором.

### Міні-бар

- Окреме прозоре вікно поверх усіх вікон.
- Початкове розташування — правий верхній кут поточного монітора.
- Працює в режимі Stand By навіть без запущеної гри.
- Показує гру, час сесії, паузу та повернення до основного вікна.
- Прозорий фон не створює чорних кутів.
- Закриття головного вікна ховає застосунок у трей, а не завершує його.

### Статистика

- Загальний час, кількість ігор і сесій.
- Playing / Backlog / Completed та completion rate.
- Топ ігор за часом, платформи, жанри й рейтинги.
- Heatmap активності за останні 26 тижнів.
- Поточний річний підсумок: години, сесії, активні дні, найдовша серія та
  «гра року» за фактичним часом сесій поточного року.
- П'ять тем: Neon, Ocean, Ember, Rose, Slate.

## Nintendo Sync (експериментальний)

- Авторизація через Nintendo OAuth у окремому вікні.
- Play activity отримується read-only; пароль не зберігається.
- Нові ігри проходять через чергу підтвердження, а ігноровані `titleId` не показуються повторно.
- Час уже імпортованих ігор оновлюється за різницею, без дублювання.
- Додатково обробляються денні записи play activity, якщо Nintendo повертає їх
  у відповіді; вони додаються як окремі сесії та допомагають обходити загальний
  ліміт відображення `150+ годин`.
- Автосинхронізація запускається у фоні кожні 30 хвилин, коли сесія Nintendo активна.
- Якщо API повертає лише округлений aggregate без денних записів, точний новий
  час автоматично визначити неможливо — потрібен повторний sync після появи
  детальнішої відповіді або ручне додавання сесії.
- Через неофіційний endpoint Nintendo цей конектор залишається експериментальним.

## Read-only веб-дашборд

Файли веб-версії лежать у [`web-dashboard`](web-dashboard/index.html).
Дашборд читає окремий Firestore-документ
`public-dashboard/dashboard`, який лаунчер публікує автоматично.

На сайт передаються лише агрегати й безпечні поля для відображення:

- кількість ігор, час, сесії та completion rate;
- статуси, платформи та жанри;
- топ ігор із назвою, обкладинкою й часом;
- останні сесії;
- активність за днями.

Нотатки, Steam App ID, кнопки запуску, завантаження та повний редагований
каталог у веб-версію не передаються.

### Публікація на Netlify

`netlify.toml` уже вказує Netlify публікувати тільки каталог `web-dashboard`.
Поточний сайт `prgtracker.netlify.app` використовує Netlify Drop, тому для
фінальної публікації треба завантажити в Netlify вміст каталогу
`web-dashboard`. Після цього dashboard стане production-версією сайту.

## Архітектура файлів

- `src/main/index.js` — Electron main-процес, Steam, трей, вікна, монітори та IPC.
- `src/preload/index.js` — безпечний міст між renderer і main.
- `src/renderer/index.html` — основний інтерфейс лаунчера та бізнес-логіка.
- `src/renderer/mini-bar.html` — floating mini-bar.
- `web-dashboard/index.html` — read-only сайт статистики.
- `netlify.toml` — налаштування публікації dashboard.

## Запуск у режимі розробки

```powershell
npx electron . --enable-logging
```

Або подвійним кліком запусти `run-dev.cmd` у корені проєкту. Dev-версія читає
код безпосередньо з `src`, тому для тестів не потрібно щоразу перевстановлювати
інсталятор. Після змін у `src/main` або `src/preload` перезапусти dev-вікно.

Після змін у `src/main` або `src/preload` потрібен повний перезапуск Electron.
Зміни лише в renderer іноді можна побачити після перезавантаження вікна.

Перевірки синтаксису:

```powershell
node --check src/main/index.js
node --check src/preload/index.js
```

Перед публічним релізом бажано окремо перевірити автозапуск і оновлення на
чистій Windows-машині.

## Windows-інсталятор

Готовий файл релізу: `release/PRGLauncher-Setup-1.2.2.exe`.

Інсталятор створює desktop і Start Menu ярлик з назвою `PRGLauncher`,
використовує зелену іконку та запускає застосунок після завершення установки.
Автозапуск Windows вмикається тільки для встановленої (packaged) версії.
При старті разом із Windows застосунок працює тихо у треї з аргументом
`--hidden`; запуск через звичайний ярлик відкриває головне вікно.

Консольне вікно не створюється: Electron-застосунок збирається як Windows GUI.
Дані користувача не видаляються під час деінсталяції (`deleteAppDataOnUninstall`
вимкнено).

## Захист і кілька користувачів

План переходу від спільного Firebase-документа до ізольованих профілів, Steam
OpenID, Firestore Rules та синхронізації без конфліктів описаний у
[`SECURITY_AND_MULTIUSER.md`](SECURITY_AND_MULTIUSER.md).

Після входу через PRG Account лаунчер зберігає каталог у персональному
Firebase-профілі та створює dashboard-посилання формату
`https://prgtracker.netlify.app/?u={profileId}`. Ідентифікатор у URL —
публічний і використовується лише для читання статистичного snapshot.

## Мова та вигляд

У «Налаштування → Загальні» можна перемикати інтерфейс між українською та
англійською. У «Вигляд» доступні теми та масштаб інтерфейсу 90–120%. Обидва
налаштування застосовуються одразу й зберігаються для наступних запусків.

Актуальний план наступних покращень зібраний у [`ROADMAP.md`](ROADMAP.md).
