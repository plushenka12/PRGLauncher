# Доступ лише власнику

Стан на 20.10.2026: owner-only `firestore.rules` розгорнуті в `gametracker-30c93`. Оновлені Netlify function і Windows-лаунчер ще не опубліковані. Налаштування прив'язане до підтвердженого власником Firebase UID `Qf6BCLccnvfJv5JEjROoxYlwhSv1`.

## Межі доступу

- Лаунчер приймає лише цей UID. Кнопку створення нового PRG Account прибрано. Email/Password і Google-вхід для власного акаунта залишаються.
- Firestore дозволяє читати й змінювати приватну бібліотеку лише цьому UID. Інші існуючі документи не видаляються, але стають недоступними через правила.
- Steam Netlify function приймає лише перевірений Firebase ID token власника.
- Опублікований `public-dashboard/<UID>` залишається доступним гостям без входу. Публічні Recap інших UID перестають читатися після деплою правил.

Видалення кнопки реєстрації **не вимикає Firebase Authentication як сервіс**: сторонній клієнт потенційно може створити Auth-користувача, але нові правила не дадуть йому доступу до бібліотеки чи Steam-функції. Уже завантажені копії старого застосунку неможливо дистанційно стерти; локальні дані на чужому пристрої це налаштування теж не видаляє. GitHub-репозиторій і старі релізи цими змінами не приховуються.

Окремо перевірити людей із доступом до Firebase/Google Cloud, Netlify й GitHub. Правила Firestore не обмежують адміністраторів хмарного проєкту, а код не може сам забрати їхні права.

## Застосування

1. Запустити `npm test`. Для фактичної перевірки Firestore rules запустити локальний емулятор і `npm run test:emulator`.
2. ✅ `firestore.rules` розгорнуті у проєкт `gametracker-30c93` після тесту в Firestore Emulator. Перед подальшим релізом вручну перевірити вхід і синхронізацію власного UID.
3. Розгорнути оновлену Netlify function. До цього старий Steam endpoint і далі прийматиме будь-який Firebase акаунт.
4. Зібрати й перевірити новий Windows-білд, потім випустити його окремим релізом. Не встановлювати оновлення автоматично під час тесту.
5. Вручну перевірити власний вхід, синхронізацію бібліотеки, Steam-імпорт і відкриття гостьової сторінки; окремим тестовим UID перевірити відмову входу та доступу до Firestore/Steam.

Зміна власного UID пізніше потребуватиме узгодженої правки лаунчера, `firestore.rules`, Netlify function і тестів. Не змінювати один шар окремо — інакше можна втратити доступ до синхронізації.
