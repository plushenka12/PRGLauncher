# Захист і багатокористувацький режим PRGLauncher

## Поточний стан

> **Актуально для 1.2.2:** PRG Account уже ізолює localStorage за Firebase UID,
> бібліотека синхронізується у `users/{uid}/profile/library`, а dashboard
> публікується у `public-dashboard/{uid}`. Нижче збережено цільові hardening-кроки
> та історичний опис старої моделі, який ще треба остаточно прибрати після
> перевірки Firestore Rules.

- Лаунчер працює локально й зберігає каталог, Backlog та сесії в `localStorage`.
- Firebase використовується для синхронізації та публікації read-only статистики.
- Наразі всі клієнти використовують один документ `gamevault/gamevault-data`.
- Запис цілого снапшота означає, що два запущені клієнти можуть перезаписати зміни один одного.
- Firebase web-конфіг не є секретом. Реальний захист визначається Firebase Authentication і Firestore Security Rules.

## Цільова модель

Кожен користувач має власний профіль:

```text
users/{uid}/games/{gameId}
users/{uid}/sessions/{sessionId}
users/{uid}/settings/{document}
public-dashboard/{uid}
```

## Onboarding першого запуску

Користувач проходить один послідовний сценарій:

1. Створює PRG-акаунт або входить через Firebase Authentication.
2. За бажанням прив'язує Steam через Steam OpenID — PRGLauncher не просить і
   не зберігає Steam-пароль.
3. Отримує play- та library-дані Steam у вигляді карток з обкладинками,
   назвами й платформою.
4. Сам відмічає ігри для імпорту та одразу задає їм статус.
5. Після імпорту лаунчер створює персональне посилання на read-only dashboard.

У майбутньому локальний режим «Продовжити без акаунта» залишається доступним,
але він не публікує дані на сайт, доки користувач не виконає вхід і не підтвердить
міграцію локального каталогу у свій профіль.

Вебсайт отримує тільки публічний агрегований snapshot конкретного профілю. Він не бачить Steam ID, нотатки, токени чи повний приватний каталог.

## Етапи реалізації

### 1. Стабільний локальний профіль

Додати `profileId`, який визначається так:

1. SteamID із локального `userdata` — якщо Steam доступний.
2. Згенерований UUID інсталяції — якщо Steam ще не авторизований.

Профіль зберігається в Electron `userData`, а не в доступному сторінці `localStorage`. Це одразу не дасть різним Windows-користувачам змішувати локальні дані.

### 2. Авторизація Firebase

Рекомендований варіант для релізу:

- Steam OpenID через невелику Netlify Function.
- Function перевіряє відповідь Steam і видає Firebase custom token.
- Electron входить у Firebase через цей token.
- Для першого запуску без Steam — тимчасовий anonymous account із можливістю прив'язати Steam пізніше.

Не зберігати Steam-логін або пароль у лаунчері. Лаунчер використовує тільки Steam OpenID і отриманий UID.

### 3. Firestore Rules

Після авторизації правила мають бути deny-by-default:

```text
match /users/{uid}/{document=**} {
  allow read, write: if request.auth != null && request.auth.uid == uid;
}

match /public-dashboard/{uid} {
  allow read: if true;
  allow write: if request.auth != null && request.auth.uid == uid;
}
```

Старий спільний документ після міграції треба закрити або залишити тільки для одноразового імпорту.

### 4. Синхронізація без перетирання

Не синхронізувати весь каталог одним `setDoc`. Кожна зміна має бути окремою операцією або подією:

- `games/{gameId}` — merge окремої гри;
- `sessions/{sessionId}` — append-only запис сесії;
- видалення — soft delete з `updatedAt`;
- конфлікти — `updatedAt`/revision і merge на рівні полів.

Тоді два клієнти одного UID можуть працювати паралельно, а сесії не будуть перебивати одна одну. Активний таймер локального клієнта не повинен завершуватися через чужий heartbeat.

### 5. Захист і відновлення

- Валідувати всі IPC-вхідні дані та Steam App ID.
- Не публікувати приватні поля в dashboard.
- Додати кнопку експорту/імпорту JSON.
- Додати резервний snapshot перед міграцією.
- Увімкнути Firebase App Check після стабілізації авторизації.
- Підписувати релізи Windows-сертифікатом перед публічним розповсюдженням.

## Що робимо першим

Перший безпечний крок — міграційний шар профілів і резервний експорт. Він не вимагає одразу ламати поточну авторизацію, але підготує дані до переходу на `users/{uid}`. Після цього підключаємо Steam OpenID/Firebase Auth і тільки тоді вмикаємо жорсткі Firestore Rules.

Для старту Firebase Authentication достатньо увімкнути Email/Password і Google
у Firebase Console. Steam OpenID підключається окремо через Netlify Function,
бо перевірка OpenID не повинна виконуватися лише в renderer Electron.

## Важливе обмеження

Якщо дві людини використовують один і той самий Steam-акаунт, SteamID буде однаковим. Для них потрібні окремі PRGLauncher-профілі всередині одного Steam-акаунта або окремий режим «не синхронізувати». Різні Steam-акаунти автоматично отримають різні профілі.
